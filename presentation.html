What is CAO?

CLI Agent Orchestrator

A framework for managing and orchestrating AI agents across different providers

  • Multi-Provider Support: Kiro CLI, Amazon Q CLI, Claude Code
  • Centralized Management: Install agents once, use everywhere
  • Standardized Format: Markdown files with YAML frontmatter
  • Reusable Agents: Generic agents work across projects

CAO Installation & Usage

# Install CAO (one-time setup)
python install_cao.py

# Create a project
python create_project.py my_migration_project

# Install agents
cd my_migration_project
python lcmp/install_agents.py

# Launch an agent
cao launch --agents migration_supervisor
# or with Kiro CLI
kiro-cli chat --agent migration_supervisor

Key Architecture Principles

1. Separation of Concerns

Agents are generic • Prompts are project-specific • Task files are runtime-specific

2. Supervisor-Based Delegation

Supervisors create task files and orchestrate work, never perform technical tasks

3. Iterative Quality Assurance

Review is built into each phase, not a separate step

4. Runtime Task Creation

Task files combine generic agents with project-specific context dynamically

Validation Framework

LCMP (Legacy Code Migration Pipeline) provides validation tools:

  • Template Validation: Ensures deliverables match template structure
  • Quality Criteria: Automated checks for completeness and correctness
  • Reviewer Validation: Human-in-the-loop quality assurance
  • Progress Tracking: JSON-based status tracking for all phases
# Validate deliverables
./validate_deliverables.sh

Path Resolution System

All paths are resolved from config/paths.cfg:

[paths]
PROJECT_BASE_PATH = /path/to/project
SOURCE_CODE = ${PROJECT_BASE_PATH}/input/legacy/source
DATABASE_ANALYSIS_REPORT = ${PROJECT_BASE_PATH}/output/analysis/database_analysis.md
TEMPLATE_BASE_PATH = ${PROJECT_BASE_PATH}/templates

Templates use placeholders like {{DATABASE_ANALYSIS_REPORT}} which are resolved at runtime by team supervisors.

End-to-End Workflow

From Setup to Deployment

Step 1: Project Setup

# One-command installation
./install_all.sh my_migration_project

# Or step-by-step
python install_cao.py
python create_project.py my_migration_project
cd my_migration_project
python lcmp/install_agents.py

This creates the complete project structure with agents, templates, and configuration.

Step 2: Prepare Source Files

Input Structure

input/
├── legacy/
│   ├── source/          # COBOL, PL/I, etc.
│   ├── database/        # DDL, schemas
│   └── specifications/  # Documentation
├── target/
│   ├── specifications/  # Target platform docs
│   └── samples/         # Sample code
└── migration/
    └── guidance/        # Migration guides

Step 3: Configure Project

Edit project-config.json:

{
  "projectName": "CardDemo Migration",
  "projectDescription": "Migration from z/OS to Cloud",
  "legacySystem": {
    "language": "COBOL",
    "framework": "CICS",
    "platform": "z/OS Mainframe",
    "database": "DB2"
  },
  "targetSystem": {
    "language": "Java",
    "framework": "Spring Boot",
    "platform": "Cloud Native",
    "database": "PostgreSQL"
  }
}

Step 4: Launch Migration Supervisor

# Using CAO
cao launch --agents migration_supervisor

# Using Kiro CLI
kiro-cli chat --agent migration_supervisor

# Using Amazon Q CLI
q chat --agent migration_supervisor

The Migration Supervisor receives the main prompt with all phases and begins orchestration.

Each status file tracks completion percentage, current step, and issues.
